Seus servidores, a um sc de distância.

sshControl é um gerenciador de conexões SSH em um único binário. Você escolhe o host num menu, passa por jump hosts, roda comandos em dezenas de máquinas de uma vez, copia arquivos e abre túneis. Tudo a partir de um config.yaml.

Conectarsc [host]

Pelo menu ou direto pela linha de comando.

Sem argumentos, o sc abre um menu com seus hosts. Com um nome, IP ou user@host:porta, conecta na hora com uma sessão interativa completa, que acompanha o redimensionamento do terminal.

Menu interativo (TUI)

Navegue pelas setas, tecle / para filtrar por nome, IP ou tag e Enter para conectar. Vários termos se combinam: @web @production mostra apenas quem tem as duas tags.

O cabeçalho mostra o usuário, o jump host e o proxy ativos, e muda conforme -u, -j e -p.

sc -j 1
🚀 SSH Control v1.0.0 | SSH User: ubuntu | Jump Host: production-jump | Proxy: FALSE
Filtro: @web @production

  │ web1
  │ 10.0.1.11 [web, production]

    web2
    10.0.1.12 [web, production, nginx]

    web3

Conexão direta

Use um host do config ou qualquer endereço. Com auto_create: true, endereços novos são salvos no config com a tag autocreated após a primeira conexão.

Usuários e jump hosts são escolhidos por nome ou pelo índice que aparece no sc -s: -u1, -j 2. 

$ sc webserver
$ sc 192.168.1.50
$ sc ubuntu@192.168.1.50:2222
$ sc -u deploy -j production-jump webserver
$ sc -u1 -j 1 webserver     # por índice

$ sc -s                     # lista tudo
$ sc -s @users              # só usuários

Comandos Remotossc -c "…" -l

Um comando, um ou muitos servidores.

Com -c, o sc executa o comando no host e sai: sc -c "uptime" webserver. Com -l, o comando roda em todos os hosts ao mesmo tempo. A saída de cada um vem separada, com o código de saída, e no final aparece um resumo com sucessos, falhas e o tempo total.

Exemplo: um grupo de servidores

O grupo @webservers tem três máquinas cadastradas no config. Com -l @webservers, o comando roda nas três ao mesmo tempo.

Os resultados aparecem na ordem em que cada host termina, não na ordem do config. 

# ~/.sshControl/config.yaml
hosts:
  - name: webserver01
    host: 10.10.0.200
    port: 22
    tags: [webservers]
  - name: webserver02
    host: 10.10.0.201
    port: 22
    tags: [webservers]
  - name: webserver03
    host: 10.10.0.202
    port: 22
    tags: [webservers]
~ — sc
$ sc -c 'date; uptime' -l @webservers

Tags por interseção v1.0

Hosts podem ter várias tags. Quando você informa mais de uma, só entram os hosts que têm todas. Hosts passados pelo nome ou IP entram sempre.

A regra vale para -s, -l, sc cp up -l, para arquivos de lista e para o filtro da TUI.

$ sc -s @web @production
HostTagsResultado
web1webproductionEntra
web2webproductionnginxEntra
staging-webwebstagingFica fora
databasedbproductionFica fora

Apenas web1 e web2 têm as duas tags.

Hosts, IPs, tags e arquivos na mesma lista

O -l aceita nomes do config, IPs, user@host:porta, tags e arquivos texto. No arquivo, os hosts podem vir um por linha ou separados por vírgula ou ponto e vírgula, e também podem ser tags. 

$ sc -c "df -h" -l web1 web2 192.168.1.50
$ sc -c "uptime" -l @web
$ sc -c "hostname" -l @production server1
$ sc -c "uptime" -l lista.txt @web
$ sc -j 1 -u admin -c "systemctl status nginx" -l @web

Túneistunnel · port-forward · -p

Leve seu navegador, suas portas e seu proxy até o outro lado.

O sshControl tem três formas de túnel sobre SSH. Todas funcionam através de jump hosts e com as mesmas opções de usuário e senha.

sc tunnel, proxy SOCKS5 v1.0

Abre uma conexão com o jump host e cria um proxy SOCKS5 em localhost:4000. Aponte o navegador para ele e acesse painéis e APIs da rede interna. Os nomes de domínio são resolvidos no jump host.

Roda em background por padrão. Use -v para acompanhar o tráfego em foreground. A porta segue --port, depois local_port_socks, depois 4000.

  1. Sua máquina 127.0.0.1:4000 Navegador com proxy SOCKS5
  2. Jump host production-jump SSH com keepalive de 30s; DNS resolvido aqui
  3. Rede interna grafana.internal Qualquer destino que o jump host alcança

Se o jump host só é alcançável por outro equipamento (uma VPN em outra máquina, por exemplo), configure routes.gateway e routes.networks. O sc cria as rotas via sudo antes de abrir o tunnel e as remove no stop. 

$ sc tunnel -j 1                        # background, SOCKS5 em localhost:4000
$ sc tunnel -j production-jump --port 5000
$ sc tunnel -j 1 -v                     # foreground mostrando o tráfego
$ sc tunnel status                      # tunnels ativos e rotas pendentes
$ sc tunnel stop -j 1                   # ou sem -j para encerrar todos

Port forward

Traz uma porta remota para a sua máquina, como o ssh -L. Cada conexão aparece no log com origem e bytes transferidos. O Ctrl+C mostra as estatísticas da sessão. 

$ sc port-forward db-server 3307:3306
$ sc port-forward -j 1 db-prod 5433:5432

Proxy reverso

O caminho contrário: o host remoto usa o proxy HTTP da sua rede. Configure proxy e proxy_port e conecte com -p. 

$ sc -j 1 -p app-server
# no host remoto:
export {https,http,ftp}_proxy=http://127.0.0.1:9999

Arquivossc cp up · down

SFTP com barra de progresso, para um host ou para vários.

sc cp down baixa arquivos para o dir_cp_default ou para o destino informado. sc cp up envia para um host ou, com -l, para vários em paralelo, aceitando tags e arquivos de lista. Use -r para copiar diretórios e ~ para a home remota. 

# download
$ sc cp down webserver /var/log/app.log
$ sc cp down -r webserver /etc/nginx/ ./nginx-backup/
$ sc cp down -j 1 db-prod /backup/dump.sql ./

# upload
$ sc cp up ./config.yaml /etc/app/ webserver
$ sc cp up -r ./dist/ /var/www/html/ webserver
$ sc cp up -l @web ./deploy.sh /opt/
$ sc cp up -l app1 app2 -j prod-jump ./app.jar /opt/app/

Autenticação-a · -P · -v

As chaves vêm primeiro. A senha, só quando precisa.

Cada conexão tenta as formas de autenticação nesta ordem e para na primeira que funciona. Quando a senha resolve, sua chave pública é instalada no servidor via SFTP, e a próxima conexão já entra pela chave.

  1. Chaves SSHTodas as chaves do usuário no config, em sequência
  2. SSH AgentAs identidades carregadas no agent
  3. SenhaPedida no terminal, ou vinda de -a ou -P
  4. Chave instaladaVai para o authorized_keys do servidor

-a Pedir a senha antes

Pede a senha uma vez, antes de conectar. Em -l, a mesma senha vale para todos os hosts.

-P Senha por variável de ambiente

Lê a senha de SCPW, sem prompt. Serve para CI/CD e scripts, e tem precedência sobre -a.

-v Modo debug

Mostra os métodos de autenticação, o status de cada chave, o caminho via jump host e o PTY. Tudo vai para o stderr.

Configuração~/.sshControl/config.yaml

Um arquivo YAML que se atualiza sozinho.

Na primeira execução, o sc cria um template comentado. A cada nova versão, as chaves que faltam no seu config são adicionadas com os valores padrão e comentários, sem mexer no que já existe.

O sc update busca a última release no GitHub, mostra as novidades e substitui o binário, guardando um backup do anterior. 

config:
  default_user: ubuntu
  auto_create: false
  dir_cp_default: ~/sshControl
  proxy: "192.168.0.1:3128"
  proxy_port: 9999
  users:
    - name: ubuntu
      ssh_keys: [~/.ssh/id_ed25519, ~/.ssh/id_rsa]
  jump_hosts:
    - name: production-jump
      host: jump.production.example.com
      user: ubuntu
      port: 22
      local_port_socks: 4000   # sc tunnel
      routes:                  # opcional
        gateway: "192.168.0.10"
        networks: ["10.20.0.0/16"]

hosts:
  - name: webserver
    host: 192.168.1.50
    port: 22
    tags: [web, production]

Instalarlinux · macos

Script de instalação

Detecta o sistema e a arquitetura, baixa a última release e instala em /usr/local/bin.

$ curl -fsSL https://sshcontrol.alexeiev.me/install | bash

Instalar em outro diretório

Use --dir para instalar sem sudo, por exemplo em ~/.local/bin.

$ curl -fsSL https://sshcontrol.alexeiev.me/install | bash -s -- --dir=$HOME/.local/bin

Compilar do código

Requer Go. O make build grava a versão e o commit no binário.

$ git clone https://github.com/alexeiev/sshControl.git $ cd sshControl $ make build
